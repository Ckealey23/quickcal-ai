## Permissions and justifications

| Permission / host | Justification |
| --- | --- |
| `activeTab` | Inject/show the floating bar on the page the user is viewing when they open QuickCalAI. |
| `scripting` | Inject content scripts/CSS needed for the bar on ordinary http(s) pages. |
| `identity` | Obtain the Google OAuth token for Calendar, Tasks, and hosted-parser account checks. |
| `storage` | Keep drafts, retry IDs, onboarding/connection state, and short-lived session UI state. |
| `offscreen` | Capture microphone audio for voice requests outside the visible page. |
| `contextMenus` | “Add to QuickCal” from highlighted text. |
| `http://*/*` and `https://*/*` | Run the bar on normal websites the user visits (not Chrome internal pages). |
| `https://www.googleapis.com/calendar/*` | Create/update/delete/read Calendar data the user authorizes. |
| `https://tasks.googleapis.com/*` | Create Google Tasks the user authorizes. |
| `https://oauth2.googleapis.com/*` | Token revocation / OAuth helpers used with Chrome identity. |
| `https://quickcal-ai.onrender.com/*` | Hosted parse, access, health, transcription, and document routes. |

## OAuth scopes (consent screen)

| Scope | Why |
| --- | --- |
| `calendar.events.owned` | Create/edit/delete events on calendars the user owns. |
| `calendar.calendarlist.readonly` | Discover calendars for conflict checks. |
| `calendar.events.readonly` | Read event details for conflict notices. |
| `calendar.events.freebusy` | Free/busy when details are unavailable. |
| `tasks` | Create tasks in the default list (no narrower write scope). |
| `userinfo.email` | Verify the connected account for the hosted parser. |

## Data-use disclosures (Store + privacy policy)

- **Remote code:** No. Extension code is packaged; AI runs on the Render backend via HTTPS.
- **User text / highlights / follow-ups:** Sent to Render → OpenAI for structured extraction.
- **Voice audio:** Captured in-extension, sent to Render `/transcribe` → OpenAI transcription; documented as in-memory on the server for the request.
- **Documents:** User-selected PDF/DOCX/TXT sent to Render for text extraction/analysis → OpenAI for proposals; Google writes only after explicit approve/create.
- **Google token:** Used by the service worker for Google APIs and as Bearer auth to Render; not exposed to the page widget.
- **Chrome storage:** Local/session state for drafts, retries, onboarding, and document review text.
- **Not claimed:** All processing on-device; permanent deletion SLAs from Google/Render/OpenAI.

## Unresolved blockers / risks

1. **GitHub Pages not enabled by this step** — privacy/homepage URLs work only after Pages is turned on for `docs/` (and after those files are on the default branch).
2. **No `icons` in `manifest.json`** — Store listing still needs uploaded images; consider adding packaged icons later if the dashboard requires them.
3. **OAuth Testing vs Production** — sensitive Calendar/Tasks scopes; Store fee alone does not verify Google OAuth. Broad users may need consent-screen Production + verification.
4. **Store item ID vs manifest `key`** — after upload, confirm the item ID still matches the Chrome-extension OAuth client’s allowed ID (`mkihiedalmccmhoebiiikpdoafhdfglf` today from the packaged key).
5. **Access mode** — production parser may still be invite-only (`ALLOWED_EMAILS`). Public Store users need `QUICKCAL_ACCESS_MODE=public` (or equivalent) when you intend open access; that is a Render config change, not done here.
6. **Remote backend availability** — free Render instances can cold-start; `/health` may be slow on first open.
